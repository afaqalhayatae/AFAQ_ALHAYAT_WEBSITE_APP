# City Pages Structure (local-SEO system)

**Date:** 2026-07-30
**Trigger:** Owner strategic instruction — every section (Maintenance,
Cleaning, Pest Control) and every individual service inside it needs its
own dedicated page per emirate, to target local search ("AC maintenance in
Dubai", "cockroach control in Sharjah", etc.). Explicitly a **structure
phase**: the routing/data skeleton had to be ready from day one, but no
content, keywords, or city pages were to be written yet.

This document describes what was built, how to publish a real city page
later, and the rules that apply when that content is written.

## What exists right now

**Zero live city pages.** Every route below is fully wired — types,
routing, metadata, internal links, phone/WhatsApp/booking CTAs, LocalBusiness
schema — but `CITY_SERVICE_CONTENT` and `CITY_SECTION_CONTENT` in
`src/lib/catalog/city-content.ts` are empty registries. `generateStaticParams()`
on every route below derives its output from those registries, so today
every one of them returns `[]`, and each route also sets
`export const dynamicParams = false`, so requesting any URL under these
routes returns a real, hard 404 — never a thin or empty page. This was
verified with `npm run build` (all 6 routes appear in the build output as
SSG routes generating exactly 0 pages).

## URL scheme

Two tiers, for all 3 sections:

**Section-level** (e.g. "Home Maintenance in Dubai"):
```
/{locale}/services/maintenance/city/{citySlug}
/{locale}/services/cleaning/city/{citySlug}
/{locale}/services/pest-control/city/{citySlug}
```
The `/city/` segment is required, not decorative — Next.js does not allow
two differently-named dynamic segments (`[slug]` and `[city]`) as siblings
under the same parent folder, so a literal `city` segment disambiguates
this from `services/maintenance/[slug]/page.tsx` and
`services/pest-control/[subService]/page.tsx`.

**Service-level** (e.g. "AC Maintenance in Dubai"):
```
/{locale}/services/maintenance/{serviceSlug}/{citySlug}
/{locale}/services/cleaning/{serviceSlug}/{citySlug}
/{locale}/services/pest-control/{subServiceId}/{citySlug}
```
`serviceSlug` is a `src/lib/catalog/services.ts` slug for Maintenance/
Cleaning; `subServiceId` is a `src/lib/catalog/pest-control-pages.ts`
sub-service id for Pest Control (e.g. `cockroach-control`) — pest types
live in their own catalog, separate from the 12 top-level services.

`citySlug` is one of the 7 emirate slugs already defined in
`src/lib/catalog/locations.ts`'s `ALL_EMIRATES` (`dubai`, `abu-dhabi`,
`sharjah`, `ajman`, `umm-al-quwain`, `ras-al-khaimah`, `fujairah`) — all 7
are structurally supported everywhere in this system, not just Dubai.

## How to publish one real city page

Add one entry to the relevant registry in `src/lib/catalog/city-content.ts`:

```ts
// Service-level, keyed "{serviceSlug|subServiceId}:{citySlug}"
CITY_SERVICE_CONTENT["ac-maintenance:dubai"] = {
  title: { en: "...", ar: "..." },        // <title>
  h1: { en: "...", ar: "..." },           // page H1
  metaDescription: { en: "...", ar: "..." },
  intro: { en: "...", ar: "..." },        // lead paragraph
  body: [{ en: "...", ar: "..." }],       // real, city-specific paragraphs
  status: "Approved — <date>",
};
```

That's the entire publishing step — no route, component, or metadata code
changes needed. The page appears automatically the next time the site is
built, already wired with:

- Title / H1 / meta description carrying the city name (from the content
  block itself, not auto-generated by template substitution)
- Breadcrumb: Home → Section → (Service →) City
- Phone number in three places: the "Call Now" CTA (`tel:` link, header
  and footer CTA rows), the WhatsApp CTA, and the LocalBusiness JSON-LD
  `telephone` field — all sourced from the single canonical
  `PHONE_E164` constant in `src/lib/brand/links.ts`
- LocalBusiness schema (`src/lib/seo/local-business.ts`) naming the page
  and its `areaServed`
- Internal-link chain: Service City Page → other services in the same
  section that also have content for that city → Booking. A section-level
  city page links forward to every service-level city page that exists
  for that city. Nothing is ever linked to a page that doesn't exist —
  `relatedLinks` is built by checking the registry, not by assuming every
  combination exists.
- `robots: noindex,follow` (`NOINDEX_FOLLOW`), matching every other
  service page on the site until the Owner lifts the sitewide indexing
  gate.

## Rules that apply once content is written (not enforced by code — editorial)

- **No copy-paste.** Each city's `intro`/`body` must be genuinely
  different from every other city's for the same service — not the same
  paragraph with the city name swapped in. The `body` field is a real
  array of paragraphs specifically so this can't collapse into one
  templated string.
- **No keyword stuffing.** Local keywords belong in natural sentences, not
  lists jammed into the copy.
- **No empty pages.** A registry entry should only be added once its
  `intro`/`body`/`h1`/`metaDescription` are real and complete — an entry
  with placeholder text is exactly the "empty page" this system is built
  to prevent, even though it would technically render.

## What was deliberately left untouched

- The pre-existing flat `/services/{slug}/{location}` route (Dubai-only,
  thin/templated, predates this system) was not modified, migrated, or
  redirected. It keeps working as-is. Whether to fold it into this system
  later (e.g. redirect it into `/services/{section}/{slug}/{city}` once
  that combination has real content) is a decision for the content phase,
  not this structure phase.
- The Maintenance/Cleaning/Pest Control hub pages do not yet link out to
  any city page (section-level or service-level) — there's nothing real
  to link to yet. Once entries exist in the registries, adding those
  links is a small follow-up, not a structural change.
- The homepage's existing "Service Areas" section (6 non-Dubai emirates
  linking to the generic `/locations` index) was not changed — that's a
  different, already-approved piece of the site and out of scope here.
